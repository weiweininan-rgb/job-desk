# Job Desk · 求职作战台

当前为 0.1.0 候选版，尚未完成独立云端验收，不是稳定发布。部署前请阅读[验证记录与剩余风险](docs/VALIDATION.md)。

给自己部署一份求职管理网站，集中记录岗位、投递和面试进度。每个使用者拥有独立的 Supabase 数据库；没有公共注册，也不提供自动代投。

## 功能

- 求职跟踪：手动添加、列表、独立滚动看板、日历、统计和 CSV 导出。
- 面试流程：记录笔试与面试、截止日期，以及打开流程时的站内提醒。
- 岗位池：Excel 导入、多职位拆分、关键词筛选、优先城市和大厂标注。
- 个人标记：置顶、暂不投递、主动放弃当前投递记录与恢复推进。
- 岗位流转：去投递后待确认，确认后转入跟踪；删除跟踪记录恢复来源岗位。
- 可选飞书：用户 OAuth 读取你有权限的指定电子表格。不开启也能使用上述功能。

默认关键词、优先城市和大厂名单均为空。关键词留空收录全部方向；城市和大厂是个人标注，不是官方排名。规则修改影响后续导入/同步，不自动重写已有记录。

## 开始使用

推荐 GitHub Pages + 自己的 Supabase 项目。先读 [部署说明](docs/DEPLOYMENT.md)；想让 AI 辅助操作，复制 [AI 部署请求](docs/AI_DEPLOY.md)。需要 GitHub、Supabase 账号，部分步骤需要本人登录或授权；项目不会自动创建付费资源。

本地使用 Node.js 24：

```sh
npm ci
npm run dev
```

先按部署说明初始化新数据库和唯一登录账号，将 .env.example 复制为 .env.local，填写自己的 URL 与 anon/publishable key。访问 http://localhost:8080。不要使用原作者的数据库或管理密钥。

## Excel 格式

点击“下载 Excel 模板”填写后导入。只读取名称含“秋招”的第一个工作表，否则读取第一个工作表。列位置必须一致；第一行填写模板表头。

| 列 | 字段 | 说明 |
| --- | --- | --- |
| A | 更新日期 | 可空，跨年请使用完整年份 |
| B | 公司 | 必填 |
| C | 职位 | 必填，多职位用换行、顿号或分号 |
| D | 批次 | 含“提前批”则归为提前批，否则归为秋招正式批 |
| E | 地点 | 用于城市标注 |
| F | 发布时间 | 可空，推荐 YYYY-MM-DD |
| G | 业务信息 | 参与关键词匹配并保存为备注 |
| H | 官方推送 | HTTP/HTTPS 链接 |
| I | 投递官网 | HTTP/HTTPS 链接；缺少时不能一键去投递 |
| J | 其他信息 | 备注、内推码等 |

导入在浏览器解析文件，然后把匹配的岗位写入自己的数据库。相同公司、职位与投递官网以指纹去重；不要导入无权使用或来源不可信的文件。只支持固定列结构，不支持任意表头自动映射。

## 可选功能与边界

飞书入口在新部署中默认关闭，启用方法、权限、密钥和限制见 [飞书说明](docs/FEISHU.md)。目前仅支持一份固定结构的电子表格，不支持任意飞书文件或多维表格。

提醒只在站内打开流程时触发，不发送邮件或浏览器后台通知。CSV 是导出功能，不是完整数据库备份。当前批次模型面向校招；社招岗位可以手动跟踪，但导入时不会自动新增社招批次。

## 开发与发布

```sh
npm run lint
npm test
npm run test:schema
npm run build
npm run release:prepare
```

初始化脚本位于 deploy/schema.sql，仅适用于空数据库。历史迁移用于既有个人实例，不能当成新实例初始化顺序。release:prepare 导出无 Git 历史、无个人配置的候选包，并附依赖许可证。发布前完成 [验收清单](docs/RELEASE_CHECKLIST.md)，不能用本地通过代替云端验收。
